# CoverAI anonymous policy demonstration — design specification

Date: 2026-10-13. Status: approved architecture; implementation not authorized by this document. Companion plan: `docs/superpowers/plans/2026-10-13-coverai-demo.md`.

## Outcome and boundaries

A visitor opens `/demo`, uploads their actual policy PDF, describes an accident, sees document-grounded excerpts with physical PDF page numbers and a cautious explanation, then creates explicitly simulated mechanic and insurance-officer inbox entries. No account, login, real claim, notification, appointment, coverage decision, payout estimate, or production record is created. The deterministic flow is a complete useful product slice before optional model assistance. Unknown information stays unknown.

Required persistent copy: **“Simulation only — no claim has been filed and no mechanic or insurer has been contacted. This is not a coverage decision.”** Explanation mode label: **“Document excerpts — deterministic, not AI-generated.”** Model mode, if separately delivered: **“External-model explanation — verify against the cited pages.”** Controls say “Create simulated handoff”, never “Submit claim”.

Production authentication, authorization, refresh cookies and role routes remain intact. Demo sessions are capability-based isolation, not production identities. `/api/v1/insurer`, `/claims`, `/policies`, `/conversations` and production storage are never invoked by demo code.

## Source-grounded constraints

Inspected working tree at HEAD `88550241f6926d6d3f894a430f0258e07a869282`, not pristine HEAD contents. Existing modified/deleted and untracked work belongs to the user. `apps/api/main.py` imports production routers, settings, metrics and scheduler; `core/config.py` requires database, Redis and Gemini settings at import time. A standalone demo app must not import main, core.config, routers/__init__.py, models, production auth or scheduler. Put demo HTTP handlers in their own package, not the production routers package whose initializer eagerly imports other routers.

`services/pdf_service.py` uses PyMuPDF text extraction, not OCR; its short-header/footer stripping can remove actual terms. Its metadata parser invents year, premium, insured value and dates. `routers/policies.py` drops page_map when persisting and supplies additional defaults. Neither is reused by the demo. `routers/insurer.py` is an existing untracked production role-protected queue/transition implementation, not an anonymous inbox.

`apps/web/src/middleware.ts` guards production prefixes and does not match `/demo`; keep its guards unchanged. `apps/web/src/lib/auth.ts` sets credentialed production API behavior; build a separate demo client. Root `.gitignore` line `lib/` hides the existing `apps/web/src/lib/{auth,api-client,store,utils}.ts`; all four must be explicitly unignored and included in the later delivery after secret review. This is a reproducibility prerequisite, not permission to replace their local contents. Current Next config has no API proxy. Existing Playwright role projects depend on authentication setup; add a separate demo config with no such dependency.

## Architecture and ownership

First delivery runs `apps/api/demo_app.py` independently, with all demo backend modules under `apps/api/demo/` and no production-service imports. Browser calls same-origin Next route handler `/api/v1/demo/[...path]`; handler forwards only to server-only `DEMO_API_ORIGIN`, allowing only the specified operations and forwarding the demo cookie/CSRF headers, never access_token, refresh_token, Authorization or arbitrary upstream headers. Production credentials therefore do not cross into the standalone process. Demo service binds locally during development; public deployment must put it behind the same-origin proxy and enforce an exact origin allowlist. Do not register anonymous handlers by weakening existing router dependencies.

A single-process bounded in-memory store is the deliberately minimal first delivery: no database, Redis, disk policy storage or external model needed. Exactly one API worker; state disappears on restart. Multi-worker/shared storage deployment is blocked until a separately reviewed scoped store exists. API startup refuses configured worker count other than one. PDF bytes are discarded immediately after successful extraction; only page text, metadata and simulation state survive until reset/expiry. Upload preview uses the browser-selected local file only; no public PDF URL is returned. No document/narrative/model contents in logs, traces, analytics, browser persistent storage or exception bodies.

## Session and resource lifecycle

POST `/api/v1/demo/session` returns a new opaque session with 256-bit random cookie `coverai_demo_session`, HttpOnly, SameSite=Strict, Secure under HTTPS, Path=/api/v1/demo, fixed Max-Age 1800. Local HTTP development alone may omit Secure. Server stores only its SHA-256 lookup digest. Body includes `expires_at` (UTC ISO timestamp), `csrf_token` (separate random 256-bit secret) and `mode: "deterministic"`. Missing/expired session never silently becomes a new session except through explicit creation. Repeated creation invalidates an existing presented session before issuing a new one. Session creation requires a matching allowed Origin; all mutation requests require both exact Origin and `X-Demo-CSRF`. Session token never appears in a URL or JSON.

Fixed TTL 30 minutes from creation, no sliding extension. DELETE `/api/v1/demo/session` invalidates the capability, removes page text, explanations, handoffs and idempotency cache atomically, and expires the cookie. Purge on access and a 60-second cleanup task; expired state cannot be read even between purges. Pending operations capture a session generation and commit only if it still exists, is unexpired and unchanged; reset/expiry/re-upload invalidates old results. Browser clears selected file and all rendered state on reset and 410, cancels requests and never accepts a late response from an older generation. Shared tabs intentionally share the cookie; independent browser contexts do not share anything.

Limits: 100 live sessions/process; 1 active PDF/session; 10 MiB upload bytes; 50 physical pages; 200,000 extracted characters/document; narrative 20–4,000 characters after trim; 10 explanations/session; 10 handoffs/session; 1 simultaneous expensive operation/session; upload parser deadline 10 seconds. Use a bounded separate worker process for parsing so timeouts terminate work, not an uncancellable thread. Maximum 2 parsing workers/process. Reject oversize request streams before buffering unbounded multipart bodies; request total cap 11 MiB including framing. Session creation 10/minute/trusted-client-IP, mutations 30/minute/session, upload 3/minute/session. Do not trust arbitrary forwarded IP headers. Capacity/rate exhaustion returns 429 with Retry-After; do not evict another visitor's live session.

## PDF and evidence contract

Accept `.pdf` extension, PDF MIME (or octet-stream only with valid extension and signature), `%PDF-` signature and successful parser validation. Reject encrypted, corrupt, empty and image-only PDFs honestly; image-only returns `OCR_NOT_AVAILABLE` and tells the user to upload a text-readable PDF. Mixed scanned/text PDFs expose unreadable page numbers and prominently state partial extraction; never claim all pages were analyzed. No OCR advertised or implemented in the first delivery. Never execute embedded scripts, attachments, links or retrieve referenced resources. Plain text extraction retains first/last lines and physical one-based page numbers; normalize only CRLF and horizontal whitespace, preserving meaningful lines.

Types defined in `demo/contracts.py`, mirrored in `apps/web/src/demo/contracts.ts`:
- `PageText`: `{page: integer>=1, text: string, readable: boolean}`.
- `Citation`: `{page: integer>=1, start: integer>=0, end: integer>start, quote: string}`; offsets are Unicode code-point offsets into canonical page text, not JavaScript UTF-16 positions. Browser displays returned quote; backend verifies `page.text[start:end] == quote`.
- `MetadataField`: `{value: string|null, status: "found"|"unknown"|"ambiguous", citations: Citation[]}`. Fields: insurer_name, policy_number, vehicle_registration, vehicle_year, premium, insured_value, start_date, end_date. Preserve original monetary/date strings; no guessed currency, dates, insured period, vehicle model/year or coverage status. Only explicitly labeled values may be found. Conflicting labeled values are ambiguous with all supporting citations. No generic number/date extraction. Unknown has null value and empty citations.
- `Document`: `{id: UUID, revision: integer, filename: string, page_count: integer, unreadable_pages: integer[], metadata: object of MetadataField}`. Filename sanitized for display only, never a storage path.
- `Explanation`: `{id: UUID, document_id: UUID, document_revision: integer, mode: "deterministic"|"external_model", narrative: string, findings: Finding[], limitations: string[], created_at: string}`.
- `Finding`: `{kind: "relevant_excerpt"|"not_found", text: string, citations: Citation[]}`. `not_found` has zero citations and exactly “No matching clause found in the readable pages. This does not establish coverage or exclusion.”
- `Handoff`: `{id: UUID, explanation_id: UUID, simulated: true, status: "simulated_created", mechanic: InboxEntry, officer: InboxEntry, created_at: string}`. `InboxEntry`: `{id: UUID, recipient: "simulated_mechanic"|"simulated_officer", title: string, narrative: string, citations: Citation[]}`. Both inbox views belong to this same session, not real roles.

Deterministic retrieval tokenizes the narrative case-insensitively, uses a versioned fixed English stopword list, ignores tokens shorter than three characters, ranks page paragraphs by distinct matching tokens, tie-breaks physical page then offset, returns up to five non-overlapping excerpts with maximum 600 code points each. No matches means abstention, not a fixture response. Findings use a fixed template “The uploaded document contains this potentially relevant wording (page N); applicability requires review.” plus the actual quote. Do not infer coverage from positive keywords or absence of an exclusion; do not suppress contrary clauses. Display selected excerpts as lexical relevance, not an exhaustive review. The original narrative is user-reported, never evidence of policy wording. Quoted malicious instructions remain quoted data.

## HTTP contract

Base path `/api/v1/demo`; JSON except policy multipart; responses `Cache-Control: no-store`, `Vary: Cookie`. No global list/search endpoints. UUID IDs are identifiers, not authorization: every lookup is through the current session. Foreign/missing IDs both return 404; missing capability 401; known expired capability 410 without leaking contents.

| Method/path | Input | Success |
|---|---|---|
| POST /session | empty JSON, allowed Origin | 201 session body and cookie |
| GET /session | cookie | 200 expires_at, mode, csrf_token, current document summary or null |
| DELETE /session | cookie, CSRF | 204; expired/missing capability also clears cookie safely |
| POST /policies | multipart file, Idempotency-Key | 201 Document; successful replacement clears prior explanations/handoffs and increments revision |
| GET /policies/{id}/pages/{page} | scoped IDs | 200 PageText; supports citation panel without exposing all visitors |
| POST /explanations | `{document_id, document_revision, narrative, mode:"deterministic"}` and Idempotency-Key | 201 Explanation |
| GET /explanations/{id} | scoped ID | 200 Explanation |
| POST /handoffs | `{explanation_id}` and Idempotency-Key | 201 Handoff; one handoff per explanation even with a new key |
| GET /inboxes/{recipient} | recipient mechanic or officer | 200 `{simulated:true, entries:InboxEntry[]}` |

Errors: `{error:{code:string,message:string,request_id:string}}`; no raw parser/provider exceptions. 400 malformed request/key, 401 session missing, 403 Origin/CSRF/consent, 404 foreign/missing item, 409 stale revision/key conflict/busy, 413 byte limit, 415 media mismatch, 422 PDF/narrative validation, 429 capacity/rate, 503 model unavailable, 504 parse/model timeout. Idempotency-Key is required UUID on policies/explanations/handoffs. Under the session lock store operation+key+canonical payload digest (PDF bytes and display filename for upload); repeat equal payload returns the original status/body without rerunning parsing/model/handoff, conflicting payload 409. Keys expire with session; errors before successful commit do not poison keys. Concurrent equal requests resolve to the same result, not duplicates. Reset invalidates replay. Mutating operations commit atomically and consume limits only on first success.

## UX acceptance

`/demo` has its own layout, no production AppShell/useUser/login redirect. Clear upload privacy notice and explicit local processing acknowledgment before upload; warning not to upload unnecessary personal details. Step sequence: policy -> narrative -> explanation -> simulated handoff. Page citations open an accessible text panel with source page, quote and partial extraction warning; optional local PDF preview may jump to page without asserting perfect extraction layout. Unknown metadata renders “Not found in readable policy text”; ambiguous renders “Conflicting values — review cited pages”. Upload failures retain no server-side document; successful replacement clearly erases previous accident/handoff state. Disable duplicate buttons while pending but enforce all limits server-side. Show actionable errors, expiry countdown, reset, keyboard focus/live regions and responsive narrow-screen layout. No fake loading AI progress.

## Optional external model: independent, gated milestone

No optional provider is necessary for milestone 1. Provider absence must not generate synthetic model output or silently return deterministic content under an AI label. A provider-enabled extension requires explicit unchecked consent per explanation disclosing provider name, exact outgoing narrative and selected excerpts, and that external retention cannot be undone by local reset. No entire PDF, cookies, metadata unrelated to the question or other session contents are sent. External mode is explicitly requested; unavailable provider returns 503 MODEL_UNAVAILABLE; offer a separate button to run deterministic mode.

Model input separates fixed system instructions from JSON-encoded untrusted narrative and excerpts. No tools/network retrieval or instruction interpolation. Treat PDF and narrative as data; delimiter tricks alone are not a security boundary. Require strict structured output: only candidate excerpt IDs and cautious connective language; server resolves citations from supplied excerpts, rejects invented pages/quotes/IDs and prohibited claim/coverage/notification promises. On invalid response fail closed, never display it. Enforce 15-second deadline, no automatic retry that repeats disclosure, one in-flight call/session, and recheck session generation/consent at commit. CI uses an explicitly identified fake transport solely to test adapter behavior; never runtime fallback content. Live-provider smoke is a separate operator check, not a skipped CI test.

## Verification and review gates

Every milestone has RED/GREEN test runs and a fresh review. Five failure classes are mandatory: (1) foreign-session ID/replay and cookie leakage; (2) corrupt/encrypted/scanned/partial/oversized PDFs and parser hangs; (3) missing/conflicting metadata and physically wrong or Unicode-broken citations; (4) narrative/PDF prompt injection, HTML and invented provider evidence; (5) concurrent retries, reset/expiry/replacement racing with work and capacity exhaustion. No skip/xfail/only/test disabling to achieve green. Existing production regression failures are reported distinctly from introduced failures, never waived silently.

Acceptance: real text PDF upload -> narrative-specific excerpts -> physical page inspection -> exactly two simulated inbox entries -> another anonymous context sees none -> reset makes all prior IDs inaccessible, while production unauthenticated routes remain protected. Deterministic execution requires no model secret or production data service. Delivery includes tracked web lib dependencies and frozen lockfile reproducibility. Documents alone do not prove these acceptance tests passed.

## Outstanding decisions and defaults

Architecture is approved; above numbers/contracts are proposed implementation defaults requiring owner review before coding. Outstanding choices: (A) accept English-only lexical retrieval/metadata labels for initial slice or specify additional language rules; default English only with explicit limitation; (B) accept single-worker ephemeral hosting or fund a separately scoped shared store; default single-worker; (C) production demo origin/hosting topology and trusted proxy IP configuration; default localhost web 3000 -> API 8001, no public launch until specified; (D) optional external provider/model, disclosure wording and retention terms; default disabled, separate approval required; (E) whether an image-only PDF must be supported in a later OCR milestone; default honest rejection; (F) accept proposed numeric limits/TTL; default values above. No fabricated sample policy is substituted for the visitor's upload. Test fixtures are explicitly synthetic and never presented as uploaded user evidence.
